## 2. 구조적 문제 3가지

### 문제 ① 딜 엔진이 딜을 생산할 수 없다 (가장 치명적)

핫딜 활성화 조건과 점수 상한이 서로 모순이다. 코드로 확인했다.

```text
활성화 조건 (src/lib/deal-detector.ts:93)
  score >= 90(special) && confidence !== "COLLECTING"

점수 상한 (src/modules/deal-engine/domain/deal-score.ts:138)
  COLLECTING → 최대 59점
  PRELIMINARY → 최대 89점   ← 90점에 절대 도달 불가
  RELIABLE   → 최대 100점
```

즉 **RELIABLE 상품만 핫딜이 될 수 있는데 RELIABLE이 0개**다.
RELIABLE 요건은 유효 샘플 20개 + 추적 30일. 현재 수집 예산이 1,296개 상품에
얇게 퍼져 상품당 평균 관측이 한 자릿수라, 이 요건을 채우는 상품이 나오지 않는다.
결과적으로 홈의 "오늘의 HOT DEAL"은 출시 이후 한 번도 켜진 적 없고
항상 폴백(미검증 관측 신호)으로 대체되고 있다.

**원인은 두 겹이다:**

1. **수집이 넓고 얕다.** 1,296개 × 관측 5회는 아무것도 증명하지 못한다.
   300개 × 관측 50회면 실제 판정이 나온다.
2. **활성화 문턱이 데이터 현실과 안 맞는다.** PRELIMINARY 상한(89)이
   special 문턱(90) 아래라, 규칙상 허용된 PRELIMINARY 활성화가 수학적으로 불가능하다.

### 문제 ② 트래픽 채널이 하나도 없다

- Google/네이버 사이트 소유확인 환경변수가 비어 있다 (`NAVER_SITE_VERIFICATION`,
  `GOOGLE_SITE_VERIFICATION` 미설정). DNS 방식으로 했을 가능성은 있으나 **등록
  여부 자체가 미확인** — SEO 전략의 전제부터 검증이 필요하다.
- 핫딜 커뮤니티 생태계(뽐뿌·알구몬·루리웹 등)와의 접점, 오픈채팅/텔레그램 채널,
  공유 루프 전부 없음.
- 폴센트(앱 400만)와 정면 대결할 브랜드도 앱도 없음. 웹뿐이다.

### 문제 ③ 아무것도 측정할 수 없다

GA·Umami·Plausible 등 어떤 분석 도구도 없다. 방문자가 몇 명인지, 어디서 오는지,
상세→쿠팡 클릭 전환이 몇 %인지 모른다. 자체 클릭 로그는 있지만 유입 퍼널이 없다.
**측정 없는 사업화 계획은 가설 검증이 불가능하다.** 무엇보다 먼저 깔아야 한다.

## 3. 포지셔닝 — 폴센트와 싸우지 않는다

| | 폴센트 | Fairprice가 갈 길 |
| --- | --- | --- |
| 채널 | 앱 (400만 다운로드) | **웹 + 검색 유입** (설치 장벽 없음) |
| 핵심 가치 | 최저가 알림 | **구매 판단** (사도 되는 가격인지 근거로 답함) |
| 데이터 표현 | 가격 그래프 | 그래프 + **원 단위 차액** + 신뢰도 명시 |
| 차별 기능 | — | **단위가격(100g당) 비교** — 경쟁 서비스에 없음 |

이미 구현된 자산 중 차별화가 되는 것: 관측가 기반 정직한 판정(신뢰도 명시),
단위가격 비교, Deal Score 근거 공개. 이걸 버리지 말고 밀어야 한다.

**집중 카테고리: 반복구매 생필품·식품.** 알림 가치가 크고(다시 사는 물건),
단위가격 비교가 가장 빛나며, 초기 수집 키워드(물티슈·커피)와도 일치한다.

## 4. 수익 모델 현실 계산

- **쿠팡 파트너스** 수수료 ~3%. 월 100만원 = GMV 3,300만원
  = 3만원 주문 1,100건 = 클릭 전환 3% 가정 시 **일 1,200 아웃바운드 클릭**.
- **AdSense** 페이지 RPM 1,000~3,000원. 월 10만 PV → 10~30만원.
  (현재는 광고 코드 미배치라 0원 — 트래픽 생기기 전 배치는 UX만 해치므로 P2에서.)

결론: **12개월 내 현실적 목표는 월 50~100만원.** 첫 6개월의 목표는 수익이 아니라
"재방문하는 트래픽"이다. 수익은 트래픽의 함수이지 독립 변수가 아니다.

리스크: 쿠팡 파트너스 단일 의존(계정 정지·API 쿼터·실적 유지 요건 — 최신 약관
확인 필요). Core가 프로바이더 중립이므로 네이버쇼핑·11번가 어댑터 추가로 완화 가능.

## 5. 로드맵

### P0 — 딜이 나오게 한다 (1~2주)

사업화의 전제. 핫딜 0개인 서비스로는 어떤 마케팅도 무의미하다.

1. **수집 집중(depth-over-breadth)**: 클릭·관심등록·골드박스 순위 상위 ~300개에
   수집 예산 집중, 나머지는 일 1회로 강등. `ProductTrackingPolicy` 티어 재배분으로
   구현 — 새 테이블 불필요.
2. **특가 이원화**: `PRELIMINARY + 80점 이상 = "특가 후보"`로 피드 노출,
   `RELIABLE + 90점 이상 = "확정 특가"` 유지. 89<90 모순을 해소하면서
   신뢰도 구분은 사용자에게 정직하게 표시한다.
3. **Umami 설치** (같은 Coolify 서버에 무료 자체 호스팅) → 측정 시작.
   앱 쪽 연동은 완료(`UMAMI_SCRIPT_URL`, `UMAMI_WEBSITE_ID`). 두 값이 채워지면
   태그가 자동으로 렌더링되고, 비어 있으면 아무것도 넣지 않는다.
4. **GSC·네이버 서치어드바이저 등록 확인 및 사이트맵 제출.**
5. 운영 마무리: UptimeRobot(`checks.reliabilityHealthy` 폴링), S3 백업, 구서버 폐기.

**완료 기준: 홈에 실제 활성 특가가 뜬다. PRELIMINARY 300개 이상.
30일 후 RELIABLE 100개 이상. 주간 지표가 수집된다.**

> **P0 완료 (2026-08-30).**
>
> | 항목 | 결과 |
> | --- | --- |
> | 1. 수집 집중 | 랭크 기반 티어(상위 100=6h·300=12h·1000=3일·나머지 주1회) + `refresh` 파이프라인 단계(런당 25건, 일 1,200건 예산) |
> | 2. 특가 이원화 | CONFIRMED(RELIABLE+90) / CANDIDATE(PRELIMINARY+80). 89<90 모순 해소 |

> | 5. 운영 | 백업 오프사이트 사본 확보·무결성 검증, UptimeRobot 2종(HTTP + `reliabilityHealthy` 키워드), 구서버 폐기 완료 |

### P1 — 첫 트래픽 (1~2개월)

1. **텔레그램/카카오 오픈채팅 딜 봇**: 활성 딜을 자동 포스팅.
   `notification-sender` 발송 경로 재사용. 초기 트래픽 채널이자 알림 채널 실험.
2. SEO 내실화: 색인 현황 측정 → 키워드 허브·카테고리 페이지 보강.
3. **웹푸시 알림**: 한국에서 이메일 열람률은 낮다. 가입 없이 구독 가능한
   웹푸시가 이메일보다 전환이 좋을 가능성이 높다.
   → 구현 완료(2026-08-30). 상세 페이지에서 가입 없이 구독하고, 파이프라인의
   `push` 단계가 신규 활성 딜을 매칭 구독자에게 발송한다. 배포 시 VAPID 키
   2개(`VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`)만 설정하면 동작한다.

**완료 기준: DAU 100 · GSC 월 노출 10,000 · 알림 구독 100.**

### P2 — 리텐션과 첫 수익 (분기)

1. **카카오 로그인** (현재 이메일 가입뿐 — 한국 웹서비스 전환의 기본기).
2. 옵션(variant) 비교 UI — 데이터는 이미 있고 노출만 안 됨 (시소픽 스타일).
3. 검색 개선: 현재 in-memory 120개 필터 → PostgreSQL `pg_trgm`.
4. AdSense 슬롯 배치 (트래픽 확보 후).

**완료 기준: 가입 500 · DAU 300 · 파트너스 첫 정산 · 월 수익 10만원.**

### P3 — 확장 판단 (6개월+)

- 제2 프로바이더(네이버쇼핑 등) 어댑터 — Deal Engine Core 범용성의 실증.
- Core 검증이 끝나야 Noljapan(여행) 착수를 판단한다. 그 전에는 손대지 않는다
  (DEAL_ENGINE_DIRECTIVE 원칙).

**완료 기준: 월 50~100만원 · MAU 10,000 · 2개 프로바이더 동시 운영.**
